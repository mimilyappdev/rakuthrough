2026年5月30日
Rakutto × RakuThrough の連携設計を考えた
相談した内容
とらのあな等の委託販売って月末にまとめて「◯個売れました」って来るじゃないですか。 あれって税務上どう扱えばいいのか、月次集計でいいのか、 振込タイミングがチャンネルごとに全部違うけどどうするのか——を相談した。
わかったこと（税務）
  • 委託売上は「月次集計でOK」。日々の個数データは不要。
  • 売上の計上タイミングは「振込が来たとき」じゃなくて「月次明細が来たとき」が正しい。
  • 明細月と入金月がズレるときは売掛金を使って管理する。
  • イベント現金売上はその場で売上計上（売掛金なし）。
→ 振込消込（売掛金→現金）は自動化できない。チャンネルごとに振込日が違いすぎるから。 RakuThrough側で「入金きた」を手動でタップする設計にする。
Rakuttoの設計で決まったこと
チャンネル設定 入金タイプ 月次連携
  • Rakuttoはまだ未実装。最初から「RakuThroughに渡しやすい設計」にする。
  • 各チャンネルに「入金タイプ」を設定する。
    • immediate（即時）：イベント現金など → RakuThroughに「現金/売上」で送る
    • deferred（後払い）：委託など → RakuThroughに「売掛金/売上」（入金待ち）で送る
  • 月次で「売上合計・仕入合計・在庫数」の3つを送るだけでOK。
  • ユーザーは委託の月次明細が来たらRakuttoに入力 → 送信ボタン1つ。
→ チャンネル設定画面がRakuttoの核心機能になる。

2026年5月30日
税務署の無料相談会に持っていく資料を作った
きっかけ
青色申告65万円控除に向けてRakuThroughの帳簿機能は一通り実装できた。 でも「これで本当に合ってるの？」が不安で、無料相談会に持っていこうと思った。 ログインなしで動作確認もできないし、仮データで資料を作ることにした。
やったこと
  • RakuThroughの申告サマリーに「印刷する（相談会用）」ボタンを追加
  • 印刷時にP/L・B/S・家事按分だけきれいに出力される @media print を実装
  • サンプルデータ入りの相談会用HTMLをデスクトップに作成
  • 相談会で聞くことリストを7カテゴリ・25問、回答メモ欄つきで作成
→ ブラウザの「印刷→PDF保存」でそのまま持参できる形になった。
相談会で確認したいこと（主なもの）
  • 委託販売（とらのあな等）の売上計上タイミングと売掛金処理
  • 鉄道模型・絵画・ハンドメイドの棚卸し管理——それぞれ科目が違う
  • 自作品が売れ残ったとき、棚卸し資産の計上はどこまで厳密にすべきか
  • アプリ開発費（ドメイン・サーバー等）は経費にできるか
  • 青色申告65万円控除はe-Tax申告で取れるか
税務上わかったこと（相談前の自習メモ）
  • 委託販売の売上は「入金時」ではなく「月次明細が来たとき」に計上するのが正しい
  • 振込タイミングはチャンネルごとにバラバラ → 売掛金で管理する設計が必要
  • 売れ残り在庫は廃棄しない限り経費にできない。棚卸し資産に計上し続ける
  • RakuThrough自体は電子帳簿保存法の要件を満たさないが、65万控除はe-Taxで取れる
  • 絵画・ハンドメイドは「自分の労働分は原価に入らない」ため、原価=材料費のみ
→ これをベースに相談会で「合ってるか？」を確認しにいく。
